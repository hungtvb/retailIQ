# Fiction unified runtime — M0 boundary

**Status:** Issue [#31](https://github.com/hungtvb/retailIQ/issues/31) owns the read-only data/SQL foundation. Bounded UC-01 chat, T04 MCP and T05 policy explanation now build on it; this is not a general Fiction or security migration. Do not interpret a local SQL PASS as Fiction E2E acceptance.

## Release and local setup

- Source: [Fiction Retail unified release](https://github.com/hungtvb/fiction-retail), `fiction-retail-unified-v1.0.0`, `main` `d92aa3fb28b9fb1b492fdc2e784b8cd4d49ebb72`.
- `data/fiction/manifest.json` is a committed **release-locked copy** of Fiction's upstream manifest. Update it only with a deliberate reviewed release upgrade.
- Obtain the **real LFS object** `data/fiction_retail.sqlite` from the Fiction repository (`git lfs pull`) or a byte-identical local copy, then put it in RetailIQ at `data/fiction/fiction_retail.sqlite`. Never commit the 199 MiB database through ordinary Git. No Supabase/cloud dependency at runtime.
- Run from repository root:

```sh
python -m scripts.verify_fiction_runtime \
  --db data/fiction/fiction_retail.sqlite \
  --manifest data/fiction/manifest.json
```

The verifier refuses a missing/wrong manifest or DB, mismatched SHA-256, row counts, embedded release metadata, broken FK/integrity, or a noncanonical UUID→SKU mapping. It also compares **independent read-only SQL oracles** for October 2026 top sellers (including contributing line counts), **all 100 case-scoped candidate decisions**, refund product-line arithmetic, a no-snapshot case, source anomalies, same-product inventory, partial periods and no-PII checks. The audit uses explicit fail-closed checks, including when Python runs with `-O`. It never repairs Fiction data.

## Implementation contract

Use `FictionStore.open(db_path, manifest_path)` from `retailiq.domain.fiction`. The constructor rejects unverified callers. **Always** pass an explicit DB path and verified manifest: Fiction queries never fall back to the old `RETAILIQ_DATA_DB` / `EL-###` fixture. Shared low-level SQL adapter retains the legacy default for unrelated, not-yet-migrated application modules. Open **once per immutable local snapshot**, not once per query: hashing the 199 MiB binary and checking DB integrity at each turn is unnecessary. A cheap file stat identity check rejects ordinary replacement/edits after verification; it is not a cryptographic adversarial file-lock or authentication boundary. The release verifier accepts only SQLite `DELETE` journal mode and rejects `-wal`/`-shm` sidecars, because committed WAL pages can differ from the pinned main-file checksum even for a read-only connection. The same sidecar guard runs before and after business reads. The release must remain immutable while the store is used. SQLite read-only `mode=ro` is deliberate; do **not** add `immutable=1` to a mutable file because SQLite can return invalid data if the file changes.

Allowed read operations: `resolve_product`, `product`, `order`, `inventory`, `top_sellers`, `refund`, `fulfillment_case`. Each returns bounded data plus canonical identifiers, source release checksum, scope, temporal context, record references and material limitations. The `query` adapter remains read-only, bounded and parameterized, not a user-supplied Text-to-SQL executor.

- **Identity:** `product_id` canonical UUID; SKU is a 1:1 reference, not a manufacturer identifier.
- **Time:** business reference is 2026-11-03 (Asia/Ho_Chi_Minh); transaction history was shifted by 916 days, not live. October calendar ranking is not the `sales_targets.month='2026-10'` cohort window. Flag partial first/last months rather than treating them as complete.
- **Money:** USD; `orders.total_amount` is recorded order value, **not settled revenue**. `refund_amount` is a recorded return amount, **not a completed payout**. Keep original `order_items.unit_price` and discounts separate from synthetic dated curated list prices. Refund product-line comparisons require valid positive quantities, prices and discounts in `[0, 100]`. Missing order-product lines yield `null` and an explicit limitation, **not** a false numeric zero or a yes/no verdict.
- **Stock:** base `inventory` has no observation timestamp; `last_restocked_date` must not be shown as freshness. An absent row for a **known** product is **missing evidence**, not zero available stock. For a valid but nonexistent SKU/UUID, return `PRODUCT_NOT_FOUND` and preserve `scope.requested_product` rather than mislabeling it `NO_INVENTORY_RECORDS`.
- **Backorder:** 100 case-scoped investigations, not a full inventory ledger. `fulfillment_case` filters candidate inputs by case/product, cutoff and both observation/receipt times, 24h age, latest eligible observation per warehouse, quantity and warehouse eligibility. The **assigned warehouse is not an alternative transfer candidate**. All snapshots remain traceable, but rejected ones carry explicit `candidate_eligible=false` and `exclusion_reasons`; eligibility records are source-referenced too. It **does not authorize** a transfer or assert that a policy remains effective. Policy validity/corroboration and manager HITL are owned by [#28](https://github.com/hungtvb/retailIQ/issues/28) and [#29](https://github.com/hungtvb/retailIQ/issues/29).
- **Aggregates:** top-seller results report contributing order-line counts plus a verifiable SQL source/measure/filter/period descriptor. `products/{id}` record refs prove only product identity, **not** a sales quantity on their own. No unbounded lists of transactional IDs are returned.
- **Privacy:** no customer name, contact, address or payment method in returned orders, refund or traces; read-only functions do not mutate source tables.
- **T04 source and time:** inventory tool accepts canonical product UUID or FR-SKU plus optional warehouse UUID, returns undated evidence only. Order tool validates order lines and shipment identities, not payment settlement. A case-linked order-status read is release-recorded, **not historical status at case cutoff**. Missing warehouse must not be confused with no stock; unsupported historical inventory queries fail closed.
